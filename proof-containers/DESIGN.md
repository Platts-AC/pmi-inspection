# Container proof page: design (keep this current every round)

**Plain names (round 5).** On screen, in the Adjust bar, the Advanced inspector and messages: Row = **Section**, Container = **Column**, Stack = **Line**, Split = **Cell**. Display text only: ids, sheet columns, tweak names and the engine keep the old words. "Tab row" in messages means a row of the Google Sheet tab and keeps that word.

**What it is.** A throwaway sandbox, separate from the PMI app: the layout engine (containers > stacks > cells) draws a header, six Job details fields and a "Find the customer" page from **rows of a Google Sheet tab**. Fake data only. No bridge code, no customer data, no tests/build.py output. Nothing in `app/`, `tests/`, the live script or the live Smart PMI sheet is touched. Every later round says here how it fits.

**Version.** proof 0.7.0 (round 7, Prompts no. 105). Round 1 = no. 95, round 2 = no. 96, round 3 = no. 100, round 4 = no. 101, round 5 = no. 103, round 6 = no. 104. The version lives in proof.js and make.py (make.py refuses to build if they differ) and in version.json, which make.py writes.

**Files.** `index.html` (built by `python3 make.py` from the engine SOURCE parts + `proof.js`), `proof.js` (everything the proof adds), `layout-profiles.csv` (starting copy of the four profile tabs, used when the sheet cannot be read), `test-script/Code.gs` (the TEST Apps Script), `test-proof.js` (round 1-2 desktop tests), `test-proof-r3.js` (round 3), `test-proof-r4.js` (round 4), `test-proof-r5.js` (round 5), `test-proof-r6.js` (round 6), `test-proof-r7.js` (round 7), `fixtures/layout-0.6.0.csv` (a 0.6.0 tab, for the migration tests); r4 to r7 use `test-harness.js`; r3 to r6 run the real Code.gs in Node; `tests-independent/` is the tester's own suite (read only for the builder); `version.json` (the published version, for the stale-page check), `README.md`.

**Test sheet** "PMI container proof (test)" (Drive: smart pmi > claude), shared "Anyone with the link: Viewer".

**Layout rows.** One row per cell. Screen `all` = sticky header on every page, `tray` = the drop-down Tools row (Tools button), anything else = a page (`entry`, `report`, `find`). Slot `box` = a real text box (call field `f:...` or Find box `find.*`); slot `results` = the Find list. Button actions: `set-view:<page>`, `reload-layout`, `toggle-tray`, `toggle-inspector`, `toggle-live`, `proof-profile`, `proof-save-tweaks`, `proof-clear-tweaks`, `proof-find`, `proof-cancel`. A bad row is refused with a plain line; the rest is drawn.

**Round 3 columns (how they fit).** Each is a plain value the engine already draws (engine/43-render-canvas.js, 4e-cell-accent.js); the code only checks it and puts it on the cell, the same way as Weight or Font size. A tab without the column loads exactly as 0.2.0 did (tested cell by cell against the 0.2.0 page). Bad value = the row is refused with a plain line.

**Cells fill (round 4).** A typing box, a button and the results list fill their whole cell, height and width (a box or button is never under 36 px), so the cell and its content grow together when a stack, row or cell weight grows. A typing box is a "face" (the border) with the real text box inside: V align places the text up / middle / down in the face, Align places it left / centre / right. Labels keep their own V align. All of this is page CSS (make.py), no engine change.

**Text size limits (round 6; replaces the round 4 16 px floor).** Every cell draws the size the tab (or the device tweak) gives, no floor. The Adjust bar's Size stops at the cell's Min size / Max size (empty = 6 to 48; the badge 9 to 24). Known trade-off: on an iPhone a value box under 16 px makes Safari zoom in when tapped; that is now the tab's choice. The TEST script keeps its own wider check (6 to 48) and did not change.

**Button feedback (round 4).** Defined ONLY in the page CSS; the sheet only CHOOSES among these looks, it never invents one. flash = a quick brighten on press (every button, unless "none"); busy = dimmed with a working label on the button itself ("Reloading...", "Saving...", "Clearing...") until the action ends, then a short green "done" ring; stay = the engine's own active look (ctl-on) while that page or mode is on (Entry, Report, Find, Tools, Adjust, Advanced, Edit). Defaults by action: set-view, toggle-*, Adjust, Profile = stay; Reload, Save tweaks, Clear mine = busy; others = flash. The optional "Press style" column overrides one button by Id (test sample: Cancel on Find = none). A "stay" on a button that has no page or mode keeps the highlight on the last such button tapped.

**Header buttons** stay one line and the same height on every width: page CSS (make.py) gives page buttons a fixed 36 px height, no wrapping, and "..." when the text does not fit. Shorter labels and the gear icon are tab data (test tabs: "New", Tools = settings icon, Pad X 4, font 11). **Id** is the stable cell id that tweaks match on (blank = made from Screen/Row/C.S.P, which breaks if cells move, so fill it). Ids must be unique.

**Profiles.** phone (auto under 700 px wide), wide (auto otherwise), android, iphone. The Profile button in Tools cycles auto > phone > wide > android > iphone > auto; the choice is remembered on the device. A missing or empty tab falls back to "Layout phone" and the bottom line says so.

**Tweaks (per device).** Rule: a device's own tweaks beat the shared tab, on that device only. The tab is never changed by the page. Device name is made once per browser (e.g. "Android Chrome 7f3a") and remembered (a home-screen icon on iPhone has its own storage, so it gets its own name). Load order: profile tab > this device's Tweaks rows for that profile > (if a save is still waiting) this device's unsent tweaks. Matched by Id; a tweak for a missing cell or with a bad value is ignored with a plain line. Saved properties (round 3): **weight, font size, label, align, wrap, pad X, pad Y, v align, nudge X, nudge Y, accent, sub label, sub label size, sub label place** of a cell. Everything else the inspector can change (row heights, stack and container weights, adding / moving / swapping cells, row colors, cell type or action, sub label nudge) shows until Reload but is NOT saved, and the bottom line then says: "This change will not be kept after Reload (not saved by Save tweaks)." (the page compares a fingerprint of those things with the one taken at load).

**Clear mine (round 4)** redraws from the last read of the tab at once (no network), keeps the selected cell and refreshes the inspector numbers; the sheet clean-up runs in the background with a busy look on the button.

**Save tweaks** sends the full list of this device's differences from the tab for the current profile ("replace"), so undoing a change removes its row. **Clear my tweaks** removes this device's rows for the current profile. A failed save keeps the tweaks on the device (marked "not saved yet") and they are still used there. The inspector can cover the Tools row on a phone, so a Save button also shows in the bottom line whenever there are unsaved changes.

**The test script** (`test-script/Code.gs`, bound to the TEST sheet, deployed as a web app "Anyone"): it can only replace/clear rows of ONE Device name + Profile on 'Tweaks', and read one device's rows. It refuses other ops, unknown properties, bad values, values starting with = + @, more than 100 rows per save, more than 2000 rows in all, bodies over 20 KB. **Openness, said plainly:** the web app is open to anyone, and its token is in this public page, so anyone who finds both could write tweak rows to the TEST sheet. That is acceptable only because the sheet holds fake layout data; never point this script or page at a real sheet.

**Reading a tab.** Google's gviz answer (no key). Gotcha: when a tab name does not exist Google sends the FIRST tab. The page checks it got the right tab (an Id column, and no other "Layout ..." heading). Read order: live tab > last good copy on the device > `layout-profiles.csv` > copy built into the page. Tweaks: the gviz table (gives the Save address), then the script's own answer when the address is known (fresher).

**Repaint rule (round 1, unchanged).** `renderCanvas` is never called while a text box has focus; typing repaints only the results cell. A Reload that arrives while typing waits for the box to be left. **Results above the keyboard:** while a Find box has focus, the results stack moves right under that box (CSS order only, nothing redrawn) and the page scrolls that box to the top.

**Reload button** re-reads layout and tweaks without reloading the browser page; the bottom line shows page version, profile, device, read time, rows, refused, tweaks, and the last action. Tap the bottom line to shrink it.

**Middle reset button and choice dot (round 5).** Every number control in the Adjust bar is minus | middle | plus. The middle shows the real number big and, small and grey, the change from the default ("+2", "-0.5") or "default"; it is orange when changed; a tap puts the default back. DEFAULT = what the layout tab gives that cell (the build already fills the engine default when the tab cell is empty: text size 12, align center; Width always comes from the Weight column). Value boxes show at least 16 px and their default the same way. A choice (Align, Wrap) that differs from the tab gets a small orange dot; tapping it puts the tab's choice back. A reset is an ordinary change: Save removes that tweak row, Revert undoes it. One-place switch to "show only the change": MID_STYLE = 'change' in proof.js (adds the class pb-change-only).

**Version badge as an ordinary cell (round 6; replaces round 5's pseudo-cell).** The badge is a real layout row, Id **badge**: Screen all, Row Header, its own narrow column at the right end of the top button line (Container 4, Column width 0.6), Type button, Content `proof-badge`, Font size 10, Align right. The engine draws it like any cell, so it moves with the frozen header and cannot cover other buttons. Migration: a tab without an Id badge row (every 0.5.0 tab) gets one added in memory (Font size / Align taken from an old Screen `badge` row if there is one). It cannot be hidden (Visible when other than always is refused). Adjust: a tap selects it like any cell; Size (9 to 24) and Align only; saved as ordinary tweaks (fontSize, align). Tap in Live: nothing visible when the page is current (no press look, no jump), reloads to the new version when it glows.

**Header in two lines (round 7, Danny's design; replaces round 6's badge column on the shipped tabs).** The Header section is ONE column with two lines: line 1 = Entry, Report, Reload, Tools (gear), New, Find (six equal cells, Line height 5, Pad X 2 so "Report" and "Reload" fit at 360 px at font 11); line 2 = blank cell `hdr.spacer1` | badge (Align center, Pad Y 0) | blank cell `hdr.spacer2` (three equal cells, Line height 2). Header = 70 px (50 + 20). Blank cells: Type text with empty Content: drawn with no border, box or text, but they are cells (selectable in Adjust; Danny fills them later). A 0.6.0 tab (badge in its own Container 4 with Column width) still loads unchanged. A 1:5 line ratio was tried on paper: line 2 would be 10 px, too thin for the badge text, so the tabs use 2:5.

**Two frozen sections (round 6).** The engine pins every frozen section at top 0, so two would sit on top of each other. The proof page stacks them itself after each draw (each gets top = the height of the frozen sections above it); this lives in proof.js only, the engine is unchanged.

**Stale page (round 5, replaces round 4's orange bar).** When version.json is newer the badge glows orange (calm pulse) and the message line says "A newer version is available (x): tap the badge"; a tap reloads with ?v=x. The page reloads ITSELF only when it is safe: nothing unsaved or waiting on the phone, no box or label in use, Adjust bar and inspector shut, no sheet call running; and only once per version in a browser session (an old cached page cannot loop). Checked on open, when the page is shown again, when back online and every 2 minutes. (The main PMI app checks at the same moments but never reloads by itself; it asks Reload / Not now.)

**Message line (round 5).** Every button message (Reloading..., Reloaded, Saved..., Clearing..., Label set, errors, the version note) goes to ONE line: inside the Adjust bar when it is open, otherwise a thin line pinned under the top buttons and kept on the visible screen (visualViewport), so the keyboard cannot hide it. One line; the long version stays in the bottom notes.

**Autofill fix C (round 7).** Every value box (Entry and Find) has autocomplete one-time-code and sits in its own form with autocomplete off (the form takes no space: display:contents). Enter never submits or reloads (the form returns false and Enter is stopped on value boxes); focus and caret stay. Keypads, placeholders, labels and neutral id / name are unchanged. Chosen from Danny's Android test of the ?autofill=1 page (only C showed no saved-phone bar and kept the phone keypad). On an iPhone a one-time-code box may offer text-message codes.

**Refresh page (round 7).** Tools tray, third line (tools.refresh, action refresh-page, busy look): reloads the whole page with ?v=<this version>&t=<time> (skips the browser's copy; other switches such as ?autofill dropped). With unsaved tweaks (or inspector changes, or tweaks still waiting on the phone) the first tap only says "Unsaved tweaks. Tap again to refresh anyway"; a second tap within 5 s reloads. For full-screen use where the browser has no menu.

**Save message (round 6).** "Saved: N changed, M total hh:mm", or "Saved: nothing new, M total hh:mm". N = tweaks added, changed or removed since the last read or save; M = all this device's tweaks for the profile.

**Autofill test page (round 6; round 7 adds the line "C is the chosen fix").** Only at the page address + `?autofill=1` (no layout read, no sheet calls). Five boxes A to E, each labelled "<letter> Phone": A = today's value box (control); B = placeholder "Type here", no phone keypad; C = autocomplete one-time-code inside a form with autocomplete off; D = read-only until tapped (restored when left); E = B + C + D. Danny reports which letters show no saved phone / address bar; no winner is applied to the real page yet.

**Autofill (round 5).** Every value box has autocomplete off, a neutral id / name (pcb- + a short code made from its Id; words like phone or address make Chrome offer saved data), autocorrect and spellcheck off, capitals only for name and address boxes. Chrome may still offer autofill; to be confirmed on Android.

**Back button (not built).** The page adds no browser history entries (switching Entry / Report / Find does not use history), so Back leaves the page. A small fix later: add one history step per page switch (history.pushState) and go to that page on popstate.

**Version badge and stale-page check (round 4).** A small badge (top right, e.g. "v0.4.0") shows the running version on every profile. On load the page fetches version.json with a time stamp (never cached); if it is newer than the running page a bar says "A newer version is available (x). Tap to reload", and the tap reloads with ?v=x&t=... so the browser cannot reuse the old copy. The page head also carries no-cache hints. A row refused for an unknown action, or a tab column the page does not know, says "this page may be out of date". Test switch: add ?pretend=0.3.0 to the address and the page acts as 0.3.0 (the badge says so), so the stale bar can be seen without publishing. Only pages from 0.4.0 on have this check; an open 0.3.0 page cannot show it.

**Phone Adjust bar (round 3).** Tools > Adjust: a bar at the bottom of the visible screen (kept above the keyboard with visualViewport). Tap a box, then ONE group at a time: Width (- / +, 0.25 steps), Size (- / +), Align (L / C / R), Wrap (on / off), Label (text box + Done), plus Revert (re-load the saved layout) and Save (the same Save tweaks). Every button is at least 44 px. Round 6: Done acts on finger LIFT (press arms it; the bar is held still from press to lift so the keyboard closing cannot move it; tester's shape: 0 of 20 taps landed on another box at 360 / 390 / 1200 px). Round 4: the other bar buttons act on PRESS (pointerdown; on phones the keyboard closing moved the bar before a release landed, so Done missed); Done commits the label, closes the box and the keyboard, goes back to the group buttons and says "Label set"; tapping the open group closes it; the bar's message is one short line ("Saved 4 tweaks 07:01"; the long one stays in the bottom line); the selected cell is kept clear of the sticky header and the bar, measured against the visible part of the screen (iPhone's visualViewport). The page scrolls so the bar never covers the selected box. While the Label box has focus only the selected cell's text is changed in place (no renderCanvas: the engine has no one-cell repaint), and the full redraw happens on Done / leaving the box. Closing the bar goes back to Live. The engine inspector stays available as Tools > Advanced and is the tool for wide screens.

**Inspector.** The engine's own inspector (not visitor mode). Tools > Advanced opens it (compact on a phone) and switches to Edit, where a tap selects a cell; closing it goes back to Live. Tool buttons (Reload, Tools, Profile, Save, Clear) still act in Edit.
