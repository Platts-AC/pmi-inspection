# Container proof page: design (keep this current every round)

**Plain names (round 5).** On screen, in the Adjust bar, the Advanced inspector and messages: Row = **Section**, Container = **Column**, Stack = **Line**, Split = **Cell**. Display text only: ids, sheet columns, tweak names and the engine keep the old words. "Tab row" in messages means a row of the Google Sheet tab and keeps that word.

**What it is.** A throwaway sandbox, separate from the PMI app: the layout engine (containers > stacks > cells) draws a header, six Job details fields and a "Find the customer" page from **rows of a Google Sheet tab**. Fake data only. No bridge code, no customer data, no tests/build.py output. Nothing in `app/`, `tests/`, the live script or the live Smart PMI sheet is touched. Every later round says here how it fits.

**Layout rows.** One row per cell. Screen `all` = sticky header on every page, `tray` = the drop-down Tools row (Tools button), anything else = a page (`entry`, `report`, `find`). Slot `box` = a real text box (call field `f:...` or Find box `find.*`); slot `results` = the Find list. Button actions: `set-view:<page>`, `reload-layout`, `toggle-tray`, `toggle-inspector`, `toggle-live`, `proof-profile`, `proof-save-tweaks`, `proof-clear-tweaks`, `proof-find`, `proof-cancel`. A bad row is refused with a plain line; the rest is drawn.

**Round 3 columns (how they fit).** Each is a plain value the engine already draws (engine/43-render-canvas.js, 4e-cell-accent.js); the code only checks it and puts it on the cell, the same way as Weight or Font size. A tab without the column loads exactly as 0.2.0 did (tested cell by cell against the 0.2.0 page). Bad value = the row is refused with a plain line.

**Cells fill (round 4).** A typing box, a button and the results list fill their whole cell, height and width (a box or button is never under 36 px), so the cell and its content grow together when a stack, row or cell weight grows. A typing box is a "face" (the border) with the real text box inside: V align places the text up / middle / down in the face, Align places it left / centre / right. Labels keep their own V align. All of this is page CSS (make.py), no engine change.

**Text size limits (round 6; replaces the round 4 16 px floor).** Every cell draws the size the tab (or the device tweak) gives, no floor. The Adjust bar's Size stops at the cell's Min size / Max size (empty = 6 to 48; the badge 9 to 24). Known trade-off: on an iPhone a value box under 16 px makes Safari zoom in when tapped; that is now the tab's choice. The TEST script keeps its own wider check (6 to 48) and did not change.

**Button feedback (round 4).** Defined ONLY in the page CSS; the sheet only CHOOSES among these looks, it never invents one. flash = a quick brighten on press (every button, unless "none"); busy = dimmed with a working label on the button itself ("Reloading...", "Saving...", "Clearing...") until the action ends, then a short green "done" ring; stay = the engine's own active look (ctl-on) while that page or mode is on (Entry, Report, Find, Tools, Adjust, Advanced, Edit). Defaults by action: set-view, toggle-*, Adjust, Profile = stay; Reload, Save tweaks, Clear mine = busy; others = flash. The optional "Press style" column overrides one button by Id (test sample: Cancel on Find = none). A "stay" on a button that has no page or mode keeps the highlight on the last such button tapped.

**Header buttons** stay one line and the same height on every width: page CSS (make.py) gives page buttons a fixed 36 px height, no wrapping, and "..." when the text does not fit. Shorter labels and the gear icon are tab data (test tabs: "New", Tools = settings icon, Pad X 4, font 11). **Id** is the stable cell id that tweaks match on (blank = made from Screen/Row/C.S.P, which breaks if cells move, so fill it). Ids must be unique.

**Profiles.** phone (auto under 700 px wide), wide (auto otherwise), android, iphone. The Profile button in Tools cycles auto > phone > wide > android > iphone > auto; the choice is remembered on the device. A missing or empty tab falls back to "Layout phone" and the bottom line says so.

**Tweaks (per device).** Rule: a device's own tweaks beat the shared tab, on that device only. The tab is never changed by the page. Device name is made once per browser (e.g. "Android Chrome 7f3a") and remembered (a home-screen icon on iPhone has its own storage, so it gets its own name). Load order: profile tab > this device's Tweaks rows for that profile > (if a save is still waiting) this device's unsent tweaks. Matched by Id; a tweak for a missing cell or with a bad value is ignored with a plain line. Saved properties (round 3): **weight, font size, label, align, wrap, pad X, pad Y, v align, nudge X, nudge Y, accent, sub label, sub label size, sub label place** of a cell. Everything else the inspector can change (row heights, stack and container weights, adding / moving / swapping cells, row colors, cell type or action, sub label nudge) shows until Reload but is NOT saved, and the bottom line then says: "This change will not be kept after Reload (not saved by Save tweaks)." (the page compares a fingerprint of those things with the one taken at load).

**Clear mine (round 4)** redraws from the last read of the tab at once (no network), keeps the selected cell and refreshes the inspector numbers; the sheet clean-up runs in the background with a busy look on the button.

**Save tweaks** sends the full list of this device's differences from the tab for the current profile ("replace"), so undoing a change removes its row. **Clear my tweaks** removes this device's rows for the current profile. A failed save keeps the tweaks on the device (marked "not saved yet") and they are still used there. The inspector can cover the Tools row on a phone, so a Save button also shows in the bottom line whenever there are unsaved changes.

**The test script** (`test-script/Code.gs`, bound to the TEST sheet, deployed as a web app "Anyone"): it can only replace/clear rows of ONE Device name + Profile on 'Tweaks', and read one device's rows. It refuses other ops, unknown properties, bad values, values starting with = + @, more than 100 rows per save, more than 2000 rows in all, bodies over 20 KB. **Openness, said plainly:** the web app is open to anyone, and its token is in this public page, so anyone who finds both could write tweak rows to the TEST sheet. That is acceptable only because the sheet holds fake layout data; never point this script or page at a real sheet.

**Reading a tab.** Google's gviz answer (no key). Gotcha: when a tab name does not exist Google sends the FIRST tab. The page checks it got the right tab (an Id column, and no other "Layout ..." heading). Read order: live tab > last good copy on the device > `layout-profiles.csv` > copy built into the page. Tweaks: the gviz table (gives the Save address), then the script's own answer when the address is known (fresher).

**Find list (round 8, Danny's design; replaces round 2's 'results under the box').** Round 2 moved the results line right under the Find box being typed in (CSS order) and put it back only when the box lost focus; on the iPhone the keyboard can close while the box keeps focus, so the list stayed between Name and Address (Danny's 13:00 screenshot). Now the list never moves: it is the Slot `results` cell in its own line under Find / Cancel. Nothing is listed until something is typed ("Type to find"); every typed word must appear (any order); a count line ("2 matches", "50 of 120: keep typing"; at most 50 drawn) sits above a small list that scrolls inside itself. Its height comes from the results line's Line height (tabs: 6 = 300 px, about 4.3 houses); without a Line height it keeps the old 330 px place (older tabs draw as before). Find boxes have the neutral hint "Search" (labels stay Name, Address, Phone).

**Tapped box in view (round 9, Danny's rule; replaces round 8's 'always scroll it under the header', which moved the page on every tap).** When a value box gets focus the page stays exactly where it is if the box is fully visible (below the frozen header and above the keyboard, from the visual viewport). Only a box partly or fully hidden is brought just into view with a 6 px gap: down from under the header, or up from behind the keyboard (never past the header), checked again when the keyboard opens (visual viewport resize). Buttons and labels never scroll. In desktop Chrome's phone mode the browser itself also centres a focused box when the viewport is small; the iPhone does not do that for a visible box (to be confirmed by Danny). Near the bottom of the page a spacer (#proof-kbpad) gives the page room to scroll; it goes away when no box has focus. Nothing is redrawn. With an iPhone-size keyboard (390 x 664 screen, 336 px keyboard, simulated) the list shows about 0.5 house under Name, 1.3 under Address, 2.1 under Phone while typing; the full list shows once the keyboard closes. Fallback Danny accepted (not built): a strip of the top three matches right above the keyboard.

**New (round 9).** Action `new-call` (Id hdr.newcall): clears every Entry value box and the saved draft (browser storage key proof-containers.call.v1), empties the Find boxes and opens Find. When something is typed in the call, the first tap only says "Tap New again to clear this call"; a second tap within 5 s clears. Before round 9 New was `set-view:find` (it only opened Find, so old text such as 'Sa' stayed); older tabs are migrated in memory (hdr.newcall with set-view:find acts as new-call). What is typed is still kept over a reload (the draft) until New.

**Structure + Items (round A, Blueprint v0.2 stage A).** Two shared tabs describe the screen for all four profiles (decision D1):
- **Structure**: one row per Line, top to bottom. Screen (all / tray / entry / find / report ...), Section, Column (lines with the same Column sit in one side-by-side column of the Section), Line name (unique; Items point to it), Cells (1 to 12), Cell widths (one share per cell, e.g. `1 2`; empty = equal; the width belongs to the Cell, so deleting or moving an Item never moves its neighbours; Danny Q-015; the column must be formatted Plain text or Google turns `1 2` into a date), Line height (as 0.7.0), Column width (only on the FIRST line of its Column), Freeze (only on the FIRST line of its Section). A value on a later line is not used and a note names the row (Danny 19:46). Section order, Column order and Line order = row order.
- **Items**: one row per Item. Id (permanent; Tweaks attach to it), Line (a Line name), Cell (1 to Cells), then the look columns of the old tabs: Type, Content, Slot, Font size, Align, Visible when, Label, Sub label, Sub label size, Sub label place, Wrap, Pad X, Pad Y, V align, Nudge X, Nudge Y, Accent, Icon, Press style, Min size, Max size. No Screen / Row / Container / Stack / Weight / Line height / Column width / Freeze.
- A Cell with no Item is drawn empty (Id `<Line name>/<cell>`); an Item with Visible when = never also leaves its cell empty (nothing moves). Lowering Cells drops the last cells; an Item in a dropped cell is refused with a plain line.
- Read: Structure and Items are read together (all or nothing). Both found and drawable -> used; one missing or without its heading -> the old `Layout <profile>` tab, exactly as 0.9.0 (rollback = rename the Structure tab); read failed -> the newest last good copy. The footer says which: "Layout read from Structure + Items", "Layout read live from the tab ...", "Layout from the last good copy of ...".
- Last good copy: after every good read the raw Structure and Items rows are stored together in the browser (localStorage key proof-containers.bundle.v1, with the time); the old tab copy stays under its own key; when the sheet cannot be read the newer of the two is drawn.
- Bad rows (Blueprint R6): one shared formula-error check (#REF!, #N/A, #VALUE!, #NAME?, #DIV/0!, #NUM!, #NULL!, #ERROR!, Loading...) on every column of every tab, the old tabs included (the #VALUE! print bug is fixed); unknown Line name, duplicate Id, duplicate Line name, two Items in one Cell, Cell outside the line, Cells not 1 to 12, bad Line height / Cell widths / Column width / Freeze: that row alone is refused with "Structure row N" or "Items row N"; an Item on a refused Line is refused with it. The rest draws.
- Converter: `node proof-containers/tools/convert-layout.js <Layout phone.csv> <folder>` writes Structure.csv and Items.csv (every Id verbatim; Cell widths from the old Weights; rows the old page refuses, such as the deliberate Weight 0 sample row, are not copied and are listed). Run once for the test sheet (round A).

**Round A.2 (0.10.2).** (1) The version badge can never be hidden or removed by a sheet row, on the old tabs or on Structure + Items: its row is the row with the action proof-badge or the Id 'badge' (named once in the code, BADGE_ID). Visible when = never is not used, a wrong Type or Content is set back to a button with proof-badge, and each comes with a note naming the tab and row; if no badge could be drawn (row missing or refused) the default badge row is added in its own column at the right of the top section, with a note. (2) Cell widths accept only whole numbers 1 to 20 with one space between them (or one number, decimals allowed, on a 1-cell line); anything else, including what Google makes of dates, times and fractions ('2 1 2001', 'Feb 1, 2001', '1-Feb', '1:02:00', '46024', '1 1/2' = 1.5), refuses that Structure row with one hint: format the column as Plain text. (3) When the sheet cannot be read and the last good copy is drawn, the banner says 'Offline: showing the saved layout' (amber); 'Reloaded HH:MM' only after a real read. The footer lines are unchanged.

**Round B1 (0.11.0, Blueprint v0.3, BD-1 to BD-6, Q-016).** Four tabs describe the screen, shared by all profiles:
- **Fields** (meaning only, 11 columns): Field Id, Name, Short label, Aliases, Kind, Unit, Hard min, Hard max, Report wording, Scope, Notes. Field Id = letters, digits and : - _ . (60 at most), unique; a missing, bad or duplicate Field Id refuses only that row ('Fields row N'). Kind: text, number, date, choice, yesno, comment, readonly, calculated (blank = text). Scope: visit, system, house (or blank). Hard min / max are stored and checked only (the warning is B2). Report wording: blank = '{label}: {value} {unit}'; typed = a template with only {label}, {value}, {unit} (any other {word} refuses the row). The built-in field list (FIELD_FALLBACK) is used ONLY for the old Layout tabs and Round A's tabs (the one allowed second home, Q-016).
- **Items** gets Field, Recipe, Join with, Join sep and Label size. A row with a Field makes its cells from its Recipe, from its Cell to the right: pieces label (Id <Id>.label), value (the value box, Id <Id>), unit (read-only unit text, Id <Id>.unit), sub-unit (no cell: the unit in the corner of the value box), spacer (Id <Id>.spacer), report-value (the report line, Id <Id>). plus and menu are refused ('built in a later stage'). Blank Recipe: report screen = report-value; a number with a Unit = label, value, sub-unit (BD-4); else label, value. Look on a Field row (BD-6): Font size, Min size, Max size = the value box; Label size = the label (and the unit text); Align, Wrap, Pad, V align, Nudge, Accent go to every piece they fit; Type, Content, Slot are not used. Label text: Items Label, else Fields Short label, else Fields Name, then the phone's Tweak. A Recipe that needs more Cells than the Line has refuses that row. Join with + Join sep (blank = ' / ') print two Fields on one report line; each value is still stored on its own. A row without a Field is a Round A row. The value box stores what is typed, nothing more (the unit is display only).
- **Profile sizes** (9 columns): Profile, Target ('*', a Line name or an Item Id, piece Ids included), Font size, Line height, Pad X, Pad Y, Min size, Max size, Notes. Only rows for the current profile apply, in the order '*', Line, Item Id, then the phone's Tweaks. Line height needs '*' or a Line. A bad row refuses only itself ('Profile sizes row N').
- **Read:** the four tabs together (all or nothing; Profile sizes optional). No Fields tab (or no 'Field Id' heading) -> Round A: Structure + 'Items (Round A)' (the frozen backup the converter wrote; rollback = rename Fields), or Structure + Items when Items has no Field rows. No Structure -> the old Layout tab. No signal -> the newest last good copy (same key proof-containers.bundle.v1, now holding Fields, Profile sizes and which Items tab too). The footer names the tabs used.
- **Plain text (PT1):** Fields Field Id, Aliases, Unit, Report wording; Items Recipe, Join sep; Profile sizes Target (and Structure Cell widths) refuse a value that Google turned into a date, time or number (Google's answer says so) or that looks like one, with ONE hint written once in the code (PT_HINT).
- **Width tweaks (BD-2, P26):** Adjust > Width is saved under '<Line name>/<Cell>' (the Cell keeps its width when the item moves); an older width tweak saved by Item Id still applies to that item's Cell until the next Save rewrites it. Look tweaks stay keyed by Id and follow the item. A move or swap is a sheet edit (Advanced's swap is not kept after Reload, as before).
- **Converter:** tools/convert-to-b1.js (Round A Structure + Items -> Fields, Items, Structure unchanged, Profile sizes, Items (Round A)). 42 rows -> 36: the 6 Entry pairs collapse; the 3 Find boxes hold a search, not call data, and stay two rows each. It writes real numbers in every size column (BD-6).
- **No 'Layout updated' pop-up (Danny, U79):** the engine's pop-up (app/src/engine/56-version-badge-and-notice.js) is hidden by CSS (make.py) and removed by proof.js; the engine still sets the old copy aside under proof_containers_backup_v1_replaced. **Offline footer:** no 'Reloaded' when the sheet was not read; the first line says 'sheet not read (offline) HH:MM' and the last-action line says what happened.

**Round B2 (0.12.0, Blueprint v0.4, BD-3, BD-5, P21 to P24, H1 rules; Q-017 and Q-018 answered in Q&A).**
- **New columns** (read by heading name; a sheet without them draws as 0.11.0): Items Input style, Wheel, Templates; Structure Templates. Plain text: Items Wheel and Templates, Structure Templates (guarded with the one hint).
- **Input style** type (blank), wheel, both. Wheel = a range '20..250 step 1 start 120' (at most 2000 choices) or a list '16x20x1, 16x25x1, 20x20x1' (2 to 200 plain-text choices). wheel: tapping the value box opens one scroll list at the bottom of the visible screen (Cancel / Done, 5 rows of 44 px, the middle row marked); the box never opens the keyboard (readonly, inputmode none); picking fills only that box and the call (no redraw). both: a small switch in the value box (◎ wheel / ⌨ keyboard); both starts on the wheel; the last mode is kept on this phone (proof-containers.inputStyle.v1, by Field Id). Input style wheel / both without a Wheel refuses the row. Hard min / Hard max (Fields): an amber 'Outside -50..600' note inside the box; never blocks, never changes the value.
- **Visible when** always, never, when-filled, reserved. never = blank cells, the Line keeps its height (as 0.11.0). when-filled = hidden until the item has a value (or revealed); reserved = hidden until revealed (a value also shows it).
- **Templates** (BD-3): blank = every template; 'PM, Repair' = only those; '-NoCool, -Quote' = every template except those; mixing is refused. Items Templates hide one item (its cells blank, width kept); Structure Templates hide the whole Line. A Line collapses only when all its items are hidden (a Line with no items never does). The version badge and its Line can never be hidden.
- **Views** (P23): set-show:all = every Line; set-show:template (start) = the template's Lines + filled Lines + Lines revealed in this call; set-show:values = only Lines with a value (Lines that hold no field, such as titles and buttons, are not touched by the View). set-template:<name> chooses the template (set-template: alone = none). reveal-hidden and the '+N hidden' chip (top right of a Section) reveal that Section's hidden Lines for this call. View, template and reveals belong to the call: kept with it on the phone (proof-containers.callview.v1), so a Chrome reload keeps them; New clears them. The footer shows 'view ..., template ...' when the layout uses any of this.
- **In place (H1):** a hidden Line's row is display:none and its Section band is shortened by that Line's own share (the same sum the engine uses), so every other Line keeps its pixels; no renderCanvas; a box being typed in is never hidden; when Lines above a focused box hide or show, the page scrolls by the same amount. A View / Template switch waits while a value box has focus. Edit / Adjust shows everything. Only one-Column Sections collapse Lines.
- **Converter** tools/convert-to-b2.js: adds the columns, Input style 'type' on the Entry Field rows, the tray Lines Tools 4 (All, Template, Values), Tools 5 (PM, NoCool, Cond., None), Tools 6 (Long test page) and the Long test page (Screen test: a title + 45 field Lines with the wheel, list wheel, both, Templates, Structure Templates, 10 when-filled and 10 reserved samples). Entry, Find and Report unchanged.

**0.18.0 (Round C3b, Prompts no. 144; I-200; Toolbox map C3 comment-picker; main app 05b-sheet-comments.js, 37h, report.js, 07-template-report-page.js).** New tab 'Comments' (P8 terms: a test-sheet tab, read with the others on its own, kept in the last good copy): like the main app's Comments tab but with ONE header row (the Field Name; Google's reader cannot take the main app's second header row); comments stacked below; a leading '*' = a default comment. A header that matches no Field Name is noted. A Field of Kind 'comment' with a column gets a pick list (#proof-pick: comments on / off, Clear, Cancel, Done = those comments, ticked; text = the main app's sentences joined); its box is read-only ('Choose comments…'). A new call pre-fills the defaults, NOT ticked (mark 'Default'); untouched defaults do not make New ask twice.
